Why this fits Neolyre

Shared data primitives

SVS needs notes, lyrics/phonemes, durations, F0, energy, and alignment. Shenghai needs the same objects to compare a learner's singing against a score.

Training feedback, not only synthesis

Instead of generating a voice for performance, Shenghai can use SVS-style acoustic features to tell singers what changed: pitch, timing, breathiness, tension, and technique.

Ethical YouTube path

Shenghai should not download unauthorized YouTube audio. The research path is licensed/local audio, user recordings, or official embeds for reference playback.

Why this matters technically

A reliable score representation is the bridge between a singer-facing practice tool and an SVS model. The same score can condition a synthesizer, generate a target F0 curve, or evaluate a user recording.

Research bridge to modern SVS

Data pipeline

Adopt SVS preprocessing concepts: vocal separation, segmentation, F0 extraction, phoneme/lyric alignment, and quality scoring. Shenghai can store the same features as practice metadata.

Reference voice for practice

Use an open SVS model to synthesize a clean target line from MusicXML, so beginners can hear their exact choral part even when no recording exists.

Analysis, not unauthorized copying

For YouTube-like songs, use official embeds or user-provided/licensed audio. Apply source separation, melody extraction, and F0 comparison only where rights and terms allow it.

Technique-aware feedback

SVS technique labels such as breathy, falsetto, intensity, or tension can become user feedback dimensions rather than only synthesis controls.
